# Markov Regime Transition Matrices

This directory contains transition matrices and configurations for economic regime modeling in the rent-vs-buy simulator.

## Directory Structure

```
scenarios/markov/
├── README.md                                    # This file
│
├── configs/                                     # 👉 USE THESE FOR SIMULATIONS
│   ├── transition_matrices/                    # Transition probability matrices
│   │   ├── expert_prior.yaml                   # Expert judgment (recommended)
│   │   ├── calibrated_v1.yaml                  # Data-driven (BIS 2023-2025)
│   │   └── empirical_only.yaml                 # Pure empirical (comparison only)
│   └── regime_distributions.yaml               # Parameter distributions per regime
│
├── calibration/                                 # 👉 HOW MATRICES ARE CREATED
│   ├── calibration_config.yaml                 # Calibration settings
│   ├── priors/                                  # Expert prior matrices for calibration
│   │   ├── prior_v1_baseline.csv               # Original expert prior
│   │   ├── prior_v2_persistent.csv             # More persistent regimes
│   │   └── prior_v3_very_persistent.csv        # Very persistent regimes
│   └── outputs/                                 # Generated by calibration script (gitignored)
│
└── docs/                                        # 👉 DOCUMENTATION
    └── (future documentation files)
```

## Quick Start

### Running Simulations

Use the transition matrices in `configs/transition_matrices/`:

```bash
# Use expert prior matrix (recommended)
python -m src.cli_time_stepping_comparison \
  --matrix-type expert \
  --scenarios scenarios/case*.yaml \
  --n-samples 5000

# Use calibrated matrix (data-driven)
python -m src.cli_time_stepping_comparison \
  --matrix-type calibrated \
  --scenarios scenarios/case*.yaml \
  --n-samples 5000
```

### Specifying Start Regime

**NEW**: You can now control which economic regime simulations start in!

#### Option 1: CLI Flag (applies to all scenarios)

```bash
python -m src.cli_time_stepping_comparison \
  --matrix-type expert \
  --start-regime CRISIS \
  --scenarios scenarios/case*.yaml \
  --n-samples 5000
```

#### Option 2: Scenario YAML (per-scenario control)

Add a `markov` section to your scenario YAML file:

```yaml
name: "My Scenario"

# NEW: Specify start regime
markov:
  start_regime: "CRISIS"  # NORMAL_GROWTH, STAGNATION, CRISIS, or RECOVERY

renting:
  rent_monthly: 1950
  # ... rest of config
```

#### Priority Order

1. **CLI `--start-regime` flag** (highest priority, overrides everything)
2. **Scenario YAML `markov.start_regime`** field
3. **Default**: Probabilistic sampling from `initial_state_probs` in transition matrix

## Regime Definitions

Based on annualized property price growth rates:

| Regime        | Annual Growth Rate | Interpretation                          |
|---------------|--------------------|-----------------------------------------|
| RECOVERY      | > 5%               | Strong property price appreciation      |
| NORMAL_GROWTH | 2% to 5%           | Healthy, sustainable growth             |
| STAGNATION    | -2% to 2%          | Flat or minimal price movement          |
| CRISIS        | < -2%              | Property price decline                  |

## Available Transition Matrices

### 1. Expert Prior (`expert_prior.yaml`)

**Recommended for most simulations.**

- **Source**: Expert judgment from [`plans/reasoning_for_priors.md`](../../plans/reasoning_for_priors.md)
- **Characteristics**: Realistic regime persistence (2-5 year durations)
- **Use when**: You want stable, theoretically-grounded transitions
- **Expected durations**:
  - NORMAL_GROWTH: 4.0 years
  - STAGNATION: 1.8 years
  - CRISIS: 2.0 years
  - RECOVERY: 1.8 years

### 2. Calibrated (`calibrated_v1.yaml`)

**Data-driven, but limited by short time series.**

- **Source**: BIS property price data (2023-Q2 to 2025-Q3)
- **Method**: 70% empirical data + 30% expert prior (Bayesian smoothing)
- **Countries**: Netherlands, Germany, Belgium, France, Austria, Denmark, Sweden, Finland, and more
- **Use when**: You want to incorporate recent market data
- **Limitation**: Short observation period (9 quarters), may not capture full economic cycle

### 3. Empirical Only (`empirical_only.yaml`)

**Pure empirical estimates without prior smoothing.**

- **Source**: BIS property price data only
- **Use when**: For comparison or sensitivity analysis
- **Warning**: High variance due to limited data, not recommended for production simulations

## Calibration

### Running Calibration

To update matrices with new data:

```bash
python scripts/calibrate_transition_matrix.py
```

This will:
1. Load BIS data from `data/bis_dp_custom_table_export_*.csv`
2. Estimate transition probabilities
3. Smooth with priors (Bayesian combination)
4. Validate and save to `calibration/outputs/`
5. Copy to `configs/transition_matrices/` for use in simulations

### Using Different Priors

```bash
python scripts/calibrate_transition_matrix.py \
  --config scenarios/markov/calibration/calibration_config.yaml
```

Edit `calibration/calibration_config.yaml` to change:
- Prior matrix path (choose from `calibration/priors/`)
- Prior weight (alpha parameter)
- Regime classification thresholds

### Creating Custom Priors

1. Copy an existing prior: `cp calibration/priors/prior_v1_baseline.csv calibration/priors/my_prior.csv`
2. Edit transition probabilities (ensure rows sum to 1.0)
3. Update `calibration/calibration_config.yaml` to point to your prior
4. Run calibration script

## Regime Distributions

The file `configs/regime_distributions.yaml` defines parameter distributions for each regime:

- **Property growth**: Mean and std dev of annual property value growth
- **Mortgage rates**: Mean and std dev of mortgage interest rates

These distributions are **independent** of the transition matrix and can be used with any matrix type.

## Validation

All transition matrices are validated for:

- ✓ **Probability constraints**: All elements in [0, 1]
- ✓ **Stochastic property**: Rows sum to 1
- ✓ **Ergodicity**: All states reachable from any starting state
- ✓ **Stability**: Stationary distribution exists and is unique

## Use Cases for Start Regime Control

### Stress Testing
Test how scenarios perform starting in worst-case conditions:
```bash
--start-regime CRISIS
```

### Scenario Comparison
Compare the same mortgage structure starting in different regimes:
```bash
# Run 1: Start in crisis
--start-regime CRISIS --scenarios case01.yaml

# Run 2: Start in recovery
--start-regime RECOVERY --scenarios case01.yaml
```

### Deterministic Analysis
Remove randomness from initial state for reproducible analysis:
```yaml
markov:
  start_regime: "NORMAL_GROWTH"
```

### Sensitivity Analysis
Test impact of starting conditions on outcomes.

## Limitations and Caveats

### Data Limitations

1. **Short time series**: Only 2023-2025 data (9 quarters)
   - Not enough to observe full economic cycle
   - May miss rare events (major crises)
   - **Mitigation**: Heavy reliance on expert prior (α = 0.3)

2. **Recent boom period**: 2023-2025 was primarily recovery/growth
   - No major crisis observed in this period
   - Crisis transition probabilities rely heavily on prior
   - **Mitigation**: Use expert prior matrix for conservative estimates

3. **Quarterly frequency**: Transitions estimated at quarterly intervals
   - Need to adjust for annual time steps in simulations
   - **Current approach**: Use annual time steps (time_step_years = 1)

### Methodological Limitations

1. **Regime classification**: Thresholds are somewhat arbitrary
   - 2% vs 3% for NORMAL/STAGNATION boundary could be debated
   - **Mitigation**: Sensitivity analysis on thresholds (future work)

2. **Homogeneity assumption**: Assumes constant transition probabilities
   - Reality: May change with policy regime, structural changes
   - **Mitigation**: Re-calibrate periodically with new data

3. **Markov property**: Assumes memoryless transitions
   - Reality: Regimes may have momentum or memory
   - **Mitigation**: Consider higher-order Markov chains in future versions

## Future Improvements

1. **Longer time series**: Extend back to 2010 or 2000 to include 2008 crisis
2. **Additional indicators**: Incorporate GDP growth, unemployment, interest rates
3. **Regime-switching models**: Hamilton (1989) approach for joint estimation
4. **Country-specific matrices**: Separate calibrations for different markets
5. **Time-varying transitions**: Allow probabilities to evolve with macro conditions
